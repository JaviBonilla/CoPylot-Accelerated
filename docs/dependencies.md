# Dependency and branch decision (2026-10-14)

Exact base SHAs/URLs are in `repos.lock.json`. All working checkouts use `feature/copilot-gpu`.

* SolarPILOT develop: `c74618a70fd8e85708957b1ee57b157ba75a5045` (2025-04-03). Use its Python API, weather files, and pysoltrace helper; its top-level CMake is GUI-only.
* Historical copilot: `739bbecc68fc994ec83828f336b278b10358d9e4` (2021-01-05). develop adds 1315 lines to copylot.py and the newer SolTrace export/multiple receiver functionality. Latest copylot change `94047588ef2a3f8f6a2db802162c5b9c022a9a8d` (2024-10-11) adds weather data generation. No technical reason to base development on copilot.
* Official SSC develop checked: `c92cbf05e3fc1411a91c0fb9b48827dd2104c7f8` (2026-10-06); default HEAD is patch `ba7a7968a115baa0c250597ce2381c7ffb27fbf2`. Neither revision contains `solarpilot/CoPilot_API.cpp` or `.h`; CMake comments the cpp out, uses `COPILOT_API`, and builds wider SAM dependencies. This disproves the assumption that the current official SSC is sufficient for CoPylot.
* The [SolarPILOT README](https://github.com/NatLabRockies/SolarPILOT/blob/c74618a70fd8e85708957b1ee57b157ba75a5045/README.md) explicitly recommends `mjwagner2/ssc:solarpilot-develop`. Its current SHA `e9469f34d4703cd71ec5eb77aa6b7a96eea8dcec` (2025-09-29) contains complete CoPilot_API, `BUILD_COPILOT_API`, recent multiple receivers/weather API/tracking angles. This is our core base, not a reconstructed API patched into official SSC.
* SolTrace current develop examined: `c33d9792d2e15408ddf1e3da963b3b0223f90d2c`. Current legacy CMake links optix_runner/embree_runner unconditionally and simdata_bridge.cpp includes their headers unconditionally, despite optional support flags. Avoid integrating this moving bridge into Phase 0. Pin published v3.4.0 `79b2ca3dfec496506d24ae56055c0d7e240ba368` (2024-10-29), retaining legacy stapi and coretrace. One explicit `<limits>` include is needed for GCC 13; no ray tracing algorithm change.

No submodules are declared in these pinned versions. SSC vendors nlopt/lpsolve/rapidxml. No wxWidgets, WEX, LK, RapidJSON, OR-Tools, GUI, network FetchContent or CUDA dependency is needed for our superbuild. CORETRACEDIR is assigned locally by CMake. The root builds only legacy SolTrace/coretrace and SSC solarpilot-develop, then selects SSC's two support source files used by CoPylot (weather/util), avoiding unrelated MPFIT/PV/battery compilation. `--no-undefined` validates the resulting dependency closure on Linux.

The public root uses conventional Git metadata. Dependency checkouts remain ignored and independent; committed mailboxes preserve their local development history.
